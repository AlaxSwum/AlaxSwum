## Docker-First Development

</div>

```
Every project starts with containers. No exceptions.

STRUCTURE                                      INFRASTRUCTURE

  docker-compose.yml       base services        API ............. Node/Python container
  docker-compose.dev.yml   dev overrides        Dev DB .......... Postgres (named volume)
  docker-compose.test.yml  test overrides       Test DB ......... Postgres (tmpfs / RAM)
  Dockerfile               production           Cache ........... Redis container
  Dockerfile.dev           dev + hot reload     Production DB ... Supabase (managed)
  Makefile                 all commands          CI/CD ........... GitHub Actions

COMMANDS                                       RULES

  make dev         start everything             Never install a database on the host machine.
  make down        stop everything              Pin every image version. No :latest.
  make test        throwaway test DB            Dev, test, and prod use the same engine.
  make seed        fill with fake data          Postgres version matches across all envs.
  make migrate     apply schema changes         One Makefile runs every command.
  make db-reset    wipe and rebuild             New branch for every task.
  make nuke        destroy everything           Tests before pushing. No exceptions.
```

## Git Workflow

</div>

```
  main ─────────────────────────────────────────────────────── production
    |                                                             ^
    +── feature/auth-system ── PR ── review ── tests pass ── merge
    |
    +── fix/signup-bug ── hotfix ── merged same day
    |
    +── refactor/api-routes ── ongoing

  Laptop (Docker)  -->  make test  -->  GitHub Actions  -->  Staging  -->  Production

  Rules: one branch per task. pull latest main first. tests pass before merge.
         migrations through CI/CD only. never commit directly to main.
```

## Principles

</div>

<table>
<tr>
<td width="50%">

**System Design** -- Clear architecture over clever shortcuts. Every system should be readable by someone who did not build it. Structure and intent should be obvious from the file tree alone.

</td>
<td width="50%">

**Maintainability** -- Code that works in six months matters more than code that is impressive today. Long-term durability over short-term hacks. Resist the urge to be clever.

</td>
</tr>
<tr>
<td width="50%">

**Operational Efficiency** -- Automate the repeatable. Document the complex. Reduce decision fatigue at every layer. If you do it twice, script it. Three times, make it a pipeline.

</td>
<td width="50%">

**Intelligent Tooling** -- AI should make workflows faster, not more complicated. Every tool is measured by whether it reduces complexity. If it adds friction, it gets replaced.

</td>
</tr>
</table>
